description: 取り込んだページを一覧から選んで replay で開く画面（http://127.0.0.1:7070/）の使い方 —— 2 つの入力欄に何を入れるか、画面に出る文の意味

`pnpm run api` で起動した API は、`/` に画面を 1 枚出します。取り込んだページを一覧から選んで、
[replay](https://github.com/uraitakahito/replay)（アーカイブを再生するビューア）で開くための画面で、
この docs では picker と呼びます。できるのは「選んで開く」だけです。ページを撮る機能も、
クロールを起こすボタンもありません。

取り込んだページは、1 ページごとに、
WACZ（Web Archive Collection Zipped）という 1 つのファイルになって保管されています。
picker の 1 行が、そのファイル 1 つです。

```
http://127.0.0.1:7070/
```

## 3 手で使う

1. **2 つの欄に名乗りを入れます。** `subject` に自分の名前、`organizations` に自分の組織の名前です。
   [クイックスタート](/capture-ledger/ja/quickstart/)のとおりに進めているなら、
   §7 の curl が送っているのと同じ値 —— `whoami` の出力と `acme` —— を入れます。
2. **「読み込む」を押します。** Enter キーでは読み込まれません。入力を変えたら、毎回押します。
3. **見たい行をクリックします。**
   別のタブで replay が開きます（[行をクリックした後](#行をクリックした後)）。

:::note[クロールの前は、空で正常です]
クロールを 1 度も起こしていなければ、「見えるアーカイブが無い」と出ます。故障ではありません。
一覧に行が増えるのは、クロール（クイックスタートの §7）が終わった後です。
:::

## 画面の部品

| 部品            | 何をするか                                                                                                                                                                                                                                               |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `subject`       | 誰として見るか。自分の名前を入れます。空のまま読み込むと `401` になります。薄い字の `alice` は入力例です                                                                                                                                                 |
| `organizations` | 自分が属している組織の名前。複数ならカンマで区切ります（薄い字の `acme,beta` が入力例）。空でも読み込めますが、見えるのは自分が起こしたクロールの成果物だけになります                                                                                    |
| 読み込む        | いまの名乗りで一覧を取り直します                                                                                                                                                                                                                         |
| 取り込んだ URL  | 取り込んだページの URL。1 行が 1 回の取り込みです。同じページを 3 回取り込めば 3 行になるので、「いつ」で見分けます                                                                                                                                      |
| いつ            | 取り込んだ日時。ブラウザの時計（手元の時間帯）で表示されます。API や DB の値は UTC です                                                                                                                                                                  |
| ラベル          | 取り込み対象（`capture_targets`）に付けておいた分類の札                                                                                                                                                                                                  |
| 欠けあり        | 4 列目に赤い字で出ます。本文を保存できなかった応答が 1 つ以上あるアーカイブです（[`wacz_complete` が `false` になるとき](/capture-ledger/ja/databases/archives/#wacz_complete-が-false-になるとき)）。開いてから気づかずに済むよう、開く前に出しています |
| さらに読む      | 次の 50 件を下に足します。続きが無くても 1 度は表示されます。押して何も増えなければ、そこで終わりです                                                                                                                                                    |
| 下の注意書き    | 名乗りで絞っているのは「一覧に出すかどうか」だけ、という断り書きです（[アーカイブ台帳](/capture-ledger/ja/archive-ledger/#ブラウザからアーカイブを選ぶ)）                                                                                                |

並びは新しい順で、1 ページは 50 件です。検索や絞り込みの欄はありません。
探すときは、ブラウザのページ内検索が使えます。

## 2 つの欄に何を入れるか

2 つの欄は「誰として見るか」の**名乗り**です。パスワードではなく、検索の条件でもありません。
入れた値は、そのままリクエストのヘッダになります。
`X-Capture-ledger-Subject` と `X-Capture-ledger-Organizations` の 2 本で、
クロールを起こすときの curl が付けているのと同じヘッダです。

名乗りによって、見える行が変わります。見えるのは、次のどちらかに当たるアーカイブです。

| 条件           | 中身                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 起こした本人   | そのクロールを起こしたときの `subject` と、いまの `subject` が同じ                                                            |
| 同じ組織の一員 | クロールは、起こした人が名乗った**先頭の**組織のものになります。見るときに同じ組織名を `organizations` に入れていれば見えます |

たとえばクイックスタートの §7 は、`whoami` の出力と `acme` でクロールを起こします。その成果物は、
`subject` に同じ名前を入れるか、`organizations` に `acme` を入れれば見えます。
別の名前だけを入れると「見えるアーカイブが無い」になります。

判定しているのは OpenFGA の `can_view` です。モデルの全体は、
[アーカイブ台帳の「認可モデル」](/capture-ledger/ja/archive-ledger/#認可モデル)にあります。

:::caution[名乗るだけで見えるのは、開発用の設定だからです]
`.env` の `CAPTURE_LEDGER_DEV_IDENTITY=1` が効いている間、API は名乗りをそのまま信じます。
画面の黄色い枠の「そのポートに届く者は、誰にでもなれる」は、このことです。

`CAPTURE_LEDGER_OIDC_ISSUER` を設定すると、API は名乗りのヘッダを無視して、
JWT（JSON Web Token —— 署名つきの身分証）だけを受け付けます。
この画面は JWT を送らないので、その構成では `401` になります
（[アーカイブ台帳の「身元」](/capture-ledger/ja/archive-ledger/#身元)）。
:::

## 画面に出る文と、その意味

| 出る文                                                             | 意味                                                 | どうするか                                                                                                   |
| ------------------------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| subject を入れて「読み込む」                                       | 開いた直後で、まだ一覧を訊いていない                 | 2 つの欄に入れて「読み込む」を押す                                                                           |
| 見えるアーカイブが無い                                             | API は正常に答えたが、その名乗りで見える行が 0 件    | 下の「空のときに確かめること」を見る                                                                         |
| 401 — subject が空か、CAPTURE_LEDGER_DEV_IDENTITY=1 になっていない | API が「誰でもない」と判断した                       | `subject` を入れる。入れても出るなら、`.env` の `CAPTURE_LEDGER_DEV_IDENTITY=1` を確かめて、API を起動し直す |
| 500 などの数字 — 一覧を取れなかった                                | API の中で失敗した（DB や OpenFGA に届かない、など） | `pnpm run api` を動かしている端末のログを見る                                                                |

### 空のときに確かめること

- **まだ何も取り込んでいない。** クイックスタートを順に進めた §6 の時点では、これが普通です。
- **名乗りが、クロールを起こしたときと違う。** 組織名の綴りを確かめます。
  迷ったら、クロールを起こしたときの curl と同じ 2 つの値を入れます。
- **クロールがまだ途中。** ページが台帳に載るのは、そのページの居た段の報告が届いた後です
  （[まだ終わっていないとき](/capture-ledger/ja/quickstart/#まだ終わっていないとき)）。
  載ってから見えるようになるまでは、長くても 5 秒ほどです ——
  API が 5 秒おきに、認可の情報を OpenFGA へ届けています。
  少し待って「読み込む」を押し直します。

## 行をクリックした後

行をクリックすると、別のタブで replay が開きます。
開く URL は、replay の場所と、その WACZ の鍵（`objectKey`）で組み立てたものです。

```
http://127.0.0.1:8899/?source=/wacz/<objectKey>
```

replay が最初に出すのは、その WACZ に入っているページの一覧です。
picker の 1 行は 1 ページの取り込みなので、ふつうは 1 件です。
**題名をクリックすると、再生が始まります。**
上の欄に元の URL と取り込んだ日時が出て、その下が、取り込んだときのページです。

replay の場所は `.env` の `REPLAY_ORIGIN` で決まります（既定は `http://127.0.0.1:8899`）。
replay のコンテナは、`pnpm run stack:up` で一緒に起動しています。

## 知っておくこと

- **入力はブラウザに覚えられます。** 次に開いたときは、前回の名乗りで自動的に読み込まれます。
  別の名乗りを試した後は、戻し忘れに注意してください。
- **この画面は誰も認証しません。** 開発用の画面です。外から届く場所には出さないでください。
- **絞っているのは一覧だけです。** WACZ の鍵を知っていれば、replay からは誰でも読めます
  （[アーカイブ台帳](/capture-ledger/ja/archive-ledger/#ブラウザからアーカイブを選ぶ)）。
