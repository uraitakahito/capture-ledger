## 回の表は作らない

**回は `crawls` の行そのものです。** `crawls` に 3 つの列を足すだけで、「いつ撮れて、いつ撮れなかったか」は既に在る行が語ります。回だけの表を作ると、同じことを 2 か所に書くことになります。

| `crawls` の列     | 意味                                                  |
| ----------------- | ----------------------------------------------------- |
| `schedule_id`     | どの予定の回か。手で始めたクロールは `NULL`           |
| `scheduled_for`   | 本来の時刻。「いま撮る」と手で始めたクロールは `NULL` |
| `schedule_missed` | 1 回にまとめた欠けの数                                |

## request と recipe

| 列        | 中身                                                   | 読む者         |
| --------- | ------------------------------------------------------ | -------------- |
| `request` | form の中身。`POST /api/crawls` と同じ形               | 「固定し直す」 |
| `recipe`  | 解決して固定した撮り方。スクリプトの本文の写しまで入る | 周回           |

シークレットは `recipe` に宣言だけを持ち、回ごとに Windmill へ訊き直します。消された変数で flow まで進まないためです。

## 行は消さない

予定を消しても `deleted_at` を立てるだけです。クロールの行が予定の名前を出すので、消すと参照先が無くなります。名前の一意は消していない行の間だけなので、消した名前は使い直せます。
