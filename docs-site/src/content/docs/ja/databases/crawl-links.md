**撮ったページにあった 1 本のリンクが 1 行です。** 主キーはリンクのあったページ（`from_page`）と、ページの中の順（`seq`）。段の報告が、ページごとの `.links.json` を読んで規則と上限を当てた、その場の判断を残します。`.links.json` は WACZ の外に在り、保管庫を作り直すと消えるので、「どのページのどのリンクを、なぜ撮らなかったか」はここにしか残りません。読み方は[リンクを 1 本ずつ残す](/capture-ledger/ja/archive-ledger/#リンクを-1-本ずつ残す)に書きました。

## どうなったか

| `outcome`   | 意味                                                                                                       |
| ----------- | ---------------------------------------------------------------------------------------------------------- |
| `followed`  | 次の段に入れた。行き先の `crawl_pages` の行の `discovered_from` が、このページ（木の辺）                   |
| `known`     | もう行がある。撮り済みへのリンク・起点へ戻るリンク・同じ段で先に別のページが見つけたリンク・自分へのリンク |
| `max_pages` | 規則は通したが、枚数の上限で入れなかった                                                                   |
| `max_depth` | 規則は通したが、深さの上限で入れなかった                                                                   |
| `closed`    | 規則は通したが、クロールが締まっていて入れなかった（締めた後に届いた段の報告）                             |
| `skip`      | 規則で落とした。`rule` が `0` なら、どの規則にも当たらなかった                                             |
| `nofollow`  | `rel="nofollow"` なので、規則を当てる前に外した。`rule` は NULL                                            |

決めるのは純粋な関数（`src/crawl/link-outcomes.ts`）で、行き先の `crawl_pages` の行（URL → 見つけたページ）から決めます。次の段に何を入れたかは渡さないので、段の報告をやり直しても、後から埋め直しても、同じ行になります。

## 1 行にする単位

- **`#` より後ろだけが違う 2 本目は書きません。** 正規化すると同じ URL です。同じ URL に `nofollow` の付いた物と付かない物があれば、付かない方を残します。
- **リンクを読まないページの行はありません。** 「撮るだけ」の先と、外へ跳ばされたページです（`.links.json` は在っても読まない）。
- **1 ページ 2,000 本まで。** 超えた分は書かず、数をログに残します。

## 段の報告で置き換える

段の報告は、終わりのトランザクションの中で、次の段のページを入れた後に、この段のページの行を**消してから入れ直します**。同じ段の報告が 2 回届いても、行は増えません。

## 記録の無いクロール

リンクが 0 本のクロールも、この表を足す前のクロールも、行は 0 です。分けるのは `crawls.links_recorded_at` で、NULL は記録の無いクロールです。前のクロールは `pnpm run links:backfill --write` が、保管庫の `.links.json` を読み直して埋めます（`.links.json` が 1 つでも無いクロールは飛ばす）。既定は数えるだけです。

## 一覧の「リンク」の数

記録の在るクロールの `crawls.pages_discovered` は、規則が通した別々の URL の数です（起点は数えない）。記録の無いクロールは、段ごとに足した延べのままです。
