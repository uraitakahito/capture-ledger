The API started by `pnpm run api` serves one screen at `/`. It lists the pages you have captured and
opens the one you pick in [replay](https://github.com/uraitakahito/replay), the viewer that plays an
archive back. These docs call it the picker. Picking is all it does: it captures nothing, and it has
no button that starts a crawl.

Each captured page is stored as one WACZ (Web Archive Collection Zipped) file. A row in the picker
is one of those files.

```
http://127.0.0.1:7070/
```

The screen is in Japanese. Its labels are quoted below as they appear, with their meaning beside
them.

## The screen follows how the API identifies callers

At startup the API settles on one way for callers to say who they are — a JWT (JSON Web Token — a
signed proof of identity), the development headers, or nothing at all. The picker changes its
fields to match.

| The API's `.env`                     | Identity        | Fields in the picker               |
| ------------------------------------ | --------------- | ---------------------------------- |
| `CAPTURE_LEDGER_OIDC_ISSUER` is set  | JWT             | One token                          |
| Only `CAPTURE_LEDGER_DEV_IDENTITY=1` | Dev headers     | Two: `subject` and `organizations` |
| Neither                              | None configured | No fields — only a notice          |

With both set it is JWT. The API never accepts both at once, so a setup with both cannot fall to
the weaker one. If you are following the [Quickstart](/capture-ledger/quickstart/), it is the dev
headers at §6 and JWT once you paste the four lines in §7. The last line of the API's startup log
says which one is in effect (`identity: …`) — see
[Check the startup log](/capture-ledger/development-environment/#check-the-startup-log).

## Three steps (dev headers)

1. **Say who you are in the two fields.** `subject` is your own name and `organizations` is the
   organization you belong to. If you are following the Quickstart, type the output of `whoami`
   and `acme` (the organization you claim when starting the crawl in §7).
2. **Press 読み込む (Load).** The Enter key does not load. Press the button again whenever you
   change a field.
3. **Click the row you want.** replay opens in a new tab — see
   [After clicking a row](#after-clicking-a-row).

## Three steps (JWT)

1. **Get a token.** In the capture-ledger directory, run the line below. The development issuer
   (`pnpm run oidc:issuer`) mints a token valid for one hour and it lands on your clipboard. The
   same command is shown inside the box on the screen.

   ```sh
   pnpm run --silent oidc:token --subject "$(whoami)" --org acme | pbcopy
   ```

2. **Paste it into the トークン (Token) field and press 読み込む (Load).**
3. **Click the row you want.**

Once loaded, the line above the list says 名前（組織）として見ている ("viewing as name
(organization)"). That is the API's verdict on the token (`GET /api/me`); the browser never reads
what is inside the token. The `--subject` and `--org` you mint the token with play the part of the
two fields under the dev headers — see [What your identity lets you see](#what-your-identity-lets-you-see).
In a deployment with a real IdP (Identity Provider — the outside service that vouches for who you
are), paste the access token that IdP issued.

:::note[Empty is normal before the first crawl]
Until a crawl has run, the picker says 見えるアーカイブが無い ("no archives visible to you").
Nothing is broken. Rows appear once a crawl (§7 of the Quickstart) has finished.
:::

works on the list.

## What your identity lets you see

Your identity is a **claim about who you are**. It is not a password, and it is not a search term.
Under the dev headers, whatever you type into the two fields is sent as two request headers,
`X-Capture-ledger-Subject` and `X-Capture-ledger-Organizations`. Under a JWT setup, the picker sends
the pasted token as `Authorization: Bearer`, and the name and organizations inside it are the claim —
the same shape as the curl that starts a crawl.

What you claim decides which rows you see. An archive is visible when either of these holds:

| Condition                        | Meaning                                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| You started the crawl            | The `subject` that started the crawl is the `subject` you typed                                                                 |
| You are in the same organization | A crawl belongs to the **first** organization its starter claimed. You see it when `organizations` names that same organization |

The Quickstart's §7, for example, starts its crawl as the output of `whoami`, in `acme`. What it
produces is visible to that same name, or to anyone claiming membership of `acme`. Any other name on
its own gives 見えるアーカイブが無い.

The decision is OpenFGA's `can_view`. The whole model is in
[The authorization model](/capture-ledger/archive-ledger/#the-authorization-model).

:::caution[A claim is enough only under the dev headers]
Under the dev headers, the API believes the claim as it stands. That is what the yellow box on the
screen means by "whoever can reach this port can be anyone". If the API listens anywhere other than
`127.0.0.1`, a red notice appears at the top of the screen (pictured in "What the messages mean"
below). Listen on `127.0.0.1` (`CAPTURE_LEDGER_API_HOST=127.0.0.1`) or go back to the JWT setup.

Under a JWT setup the API accepts only a JWT. The development issuer that mints tokens listens only
on `127.0.0.1`, so nobody else on the network can claim to be anyone — see
[Identity](/capture-ledger/archive-ledger/#identity).
:::

### When the list is empty

- **Nothing has been captured yet.** At §6 of the Quickstart this is the normal state.
- **The identity differs from the one that started the crawl.** Check the spelling of the
  organization. When in doubt, claim the same name and organization that started the crawl (under a
  JWT setup, the `--subject` and `--org` you mint the token with).
- **The crawl is still running.** A page enters the ledger once the level it belonged to has been
  reported — see [While it is still running](/capture-ledger/quickstart/#while-it-is-still-running).
  From there it takes at most about five seconds to become visible: the API delivers authorization
  data to OpenFGA every five seconds. Wait a moment and press 読み込む again.

## After clicking a row

Clicking a row opens replay in a new tab. The URL is built from where replay lives and the key of
that WACZ (`objectKey`):

```
http://127.0.0.1:8899/?source=/wacz/<objectKey>
```

replay first shows the list of pages inside that WACZ. One picker row is the capture of one page, so
there is normally one entry. **Click its title and playback starts.** The bar at the top shows the
original URL and the capture time; below it is the page as it was captured.

Where replay lives comes from `REPLAY_ORIGIN` in `.env` (default `http://127.0.0.1:8899`). The replay
container is started along with the rest by `pnpm run stack:up`.

## Good to know

- **The browser remembers the two name fields.** Next time the page opens it loads under the previous
  identity on its own. After trying another identity, remember to change it back.
- **A token is gone when you close the tab.** A token is itself a key, so the picker keeps it only for
  the tab (`sessionStorage`). Paste it again after reopening — and after it expires in an hour.
- **The picker mints no tokens.** The development issuer does, and it listens only on `127.0.0.1`.
- **Under the dev headers the screen authenticates nobody.** It is a development screen. Do not expose
  it anywhere reachable from outside.
- **Only the list is filtered.** Anyone who knows the key of a WACZ can read it through replay — see
  [Archive ledger](/capture-ledger/archive-ledger/#picking-an-archive-in-a-browser).
